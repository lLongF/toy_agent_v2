当前仓库在测什么

评测对象是线上玩具 Agent。测试侧只发文本、收回复和 MCP 调用，对照 Excel「预期结果」打分。每个玩具只换三样：token、测试样例、工具描述。OTA / 设备 / 双裁判全仓库共用。

采集OTA → WS → hello / tools/list → 按类型发「消息列表」
判分Qwen ∥ DeepSeek 均分 ≥ 0.7；MCP「是」走规则

从 CLI 脚本到完善评测系统

现有 text_input_test.py 已经把「建连 → 分类型采集 → 双裁判 → 出报告」跑通。完善的系统不是重写协议，而是在这条链路上补齐：用例治理、运行编排、可观测、人审、回归和对外交付。

L1 资产层玩具档案 · 版本化用例集 · MCP 工具清单 · 裁判 Prompt 库
L2 编排层Run Orchestrator：队列、按类型会话、并发评分、失败重试、每日 schedule
L3 判定层规则裁判（MCP）+ 多 LLM 裁判 + 人审覆盖；评分失败与业务不通过分列
L4 运营层看板、分歧队列、跨玩具榜、回归告警、xlsx/md/json、企微
1 选玩具toys/<id>/toy.json
2 建连OTA 换 WS url/token
3 采集类型隔离会话
4 双裁判采集完再并发打分
5 交付报告 + 企微 + 回归
