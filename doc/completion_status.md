## 实际验证

命令：`.venv/bin/python -m unittest discover -s tests -v`

最新结果：**40 项测试全部通过**（macOS ARM64 / Python 3.11.4）。

本轮新增验证包括：

- 真实本机 MCP HTTP / SSE 服务与工具定义接入设备 tools/list。
- 独立 `ui_worker.py` 进程 → 本机 OTA HTTP → 真实 WebSocket → OpenAI SDK HTTP → 三种报告文件，成功完成。
- AppTest 从页面保存用例、工具来源、分类和单条阈值，均核对实际文件内容及备份。
- 事件真实调用 run_framework，只运行选定用例；重复 ID 不重跑，通知失败报告仍在。
- 模拟北京时间边界验证每日触发与日期去重；实际监听进程启停后状态与锁正确更新。
- 筛选后 Excel 行数与 JSON/通知一致；OTA 失败时只统计未执行，不当作业务失败。
- 缺少类别、编号、预期的异常行不会在维护视图中丢失，修复后可再次执行。
- 用例源文件最终仍为原始 98 条，正式 reports 目录未写入模拟评测记录。

## 部署边界

- 标准 MCP 仅用于发现工具描述，不把评测变成真实物理设备工具执行器。
- 单条阈值未配置时仍沿用默认 0.7，不擅自制定业务标准。
- 定时进程需持续运行；机器重启后需由部署侧重新启动。GitLab 与本地每日计划只启用一种。
- 本地同工作区 OS 文件锁不是跨机器分布式锁。
- 4 小时上限代码已实现，未实际等待 4 小时；Windows 强制停止路径待目标 Runner 验收。
