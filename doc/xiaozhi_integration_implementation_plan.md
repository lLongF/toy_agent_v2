# 小智官方服务接入与多 Agent 对比评测完整实施方案

> 状态：待确认、待实施。本文件不是接通声明，也不是自动执行授权。
> 依据：现有多 Agent 路线图、用户提供的小智官方接入方案及当前源码。
> 本期目标：在获授权且经过验证的入口下，复用现有平台，完成自家与小智官方指定角色的公共文本评测闭环。
> 本次工作仅产出方案，未调用官方服务、未修改业务代码、未重判历史报告。

## 1. 核心决策

1. 先验证小智官方实际入口，再实施对应适配器；不能把换一个OTA地址当作接入完成。
2. 复用玩具档案、公共测试集、自定义类型、动态裁判、快照、独立进程和报告；不重建平台。
3. 增加薄适配器契约、总任务/子任务编排、统一结果及对比视图。
4. 首期只做两个对象、公共文本、串行受控执行。保留以后增加厂商的接口，不实现任意协议配置器。
5. 当前JSON/目录存储足以支撑首期单机闭环，暂不执行路线图中的SQLite建议；这是一项主动缩小影响面的选型，不代表永不需要数据库。
6. 工作任务、语音全链路、真实硬件工具、长期记忆和知识库共同排名不纳入首期。

## 2. 两份原方案与当前代码的差异

两份方案的总体方向一致：以适配器隔离厂商，以公共用例统一评分，以总任务汇总独立子任务。路线图是长期方向，小智方案是首个厂商落地约束；具体协议以官方确认与实测为准。

当前平台已比原路线图更完善，不应重复开发：

| 能力 | 当前实际基础 | 本期处理 |
|---|---|---|
| 玩具管理 | 名称、内部ID、启停、环境/能力后端；当前新增/编辑弹窗仅名称和真实Token | 保留简易入口，只为外部接入增加高级配置，不恢复大段JSON主表单 |
| 凭据 | 玩具Token及裁判Key可Windows DPAPI加密；环境变量兼容；worker使用stdin | 复用；外部鉴权分字段保存，不把所有服务统一叫玩具Token |
| 测试集 | 公共/所属专属集、Excel维护、复制、快照、来源映射、跨集会话隔离 | 复用公共集；对比任务禁止使用对方专属集 |
| 自定义类型 | 名称映射已有执行方式，独立rubric及阈值 | 复用，不把厂商名作为类别，不把新增类别误当新协议支持 |
| 裁判 | 动态模型、运行多选、等权平均、任一失败记评分失败 | 总任务固定同一套裁判配置和规则，所有子任务复用 |
| 工具规则 | 嵌入式工具定义、tools/call名称精确匹配、0/1规则分 | 自家专项保留；小智公共首期不强制注入、不要求设备工具证据 |
| 设备链路 | OTA→WS→hello→listen，模拟设备MCP占位回包 | 作为自家适配实现保留，不能直接当小智官方协议实现 |
| 任务 | 单玩具独立进程、状态文件、日志、设备锁；可多测试集但非多Agent总任务 | 增加父任务、子任务、失败隔离、恢复查询和对比汇总 |
| 报告 | schema_version=2、JSON/Excel/Markdown、动态裁判列和来源映射 | 新增对比报告版本，不覆盖旧读取和原独立报告 |
| 验证基线 | 最近开发记录90项本地测试：89通过、1既有Windows跳过 | 作为历史本地基线；新改动必须重新回归，不等于小智已接通 |

源码依据：toy_profiles.py、local_credentials.py、dataset_store.py、category_store.py、judge_store.py、judge.py、text_input_test.py、collection.py、ui_jobs.py、ui_results.py。当前没有通用官方小智适配器、父子多Agent任务或同题对比报告。

## 3. 被测对象定义与授权前置

### 3.1 对象身份

被测对象应记录为“小智官方服务 / 指定角色 / 配置修订 / 测试日期”，而非笼统“小智模型”。自建社区后端、底层模型API和官方产品分别登记，不互相代替。

每个对象保存稳定平台ID、展示名称、供应方、服务归属、目标角色/绑定说明、接入路线、适配器版本、可确认配置摘要。平台内部ID与官方角色标识分开；若官方是设备绑定角色，不臆造请求agent_id字段。

### 3.2 接入调查清单

| 必须确认 | 所需证据 | 责任人 |
|---|---|---|
| 官方账号、目标角色、专用设备与绑定关系 | 授权账号下配置记录或官方确认 | 测试/业务负责人 |
| 程序接入与自动化测试允许范围 | 官方说明、协议条款或书面许可 | 业务负责人 |
| API/设备客户端入口 | 官方地址、鉴权方式和版本资料 | 开发+测试 |
| 文本直入语义 | 官方说明与单条实际请求/完整响应 | 开发 |
| 会话隔离、重连、历史残留 | 双会话及断连验证记录 | 开发+测试 |
| 完成标志、片段归并、工具可观察性 | 脱敏事件样本 | 开发 |
| 频率、并发、额度、测试数据范围 | 明确限额和审批 | 业务/测试负责人 |

没有这些条件时，可先开发通用契约和模拟测试，不能调用真实官方服务或宣布接通。不得随机生成MAC充当授权设备，不提取第三方账号Cookie、不绕过激活。

### 3.3 路线选择

A 官方文本API：优先；按已确认实际接口实现。
B 获授权设备/软件客户端协议且支持文本：次选；按对应版本握手、鉴权、输入和结束语义实现。
C 只有音频：另立语音链路方案；固定音频、编解码、ASR/TTS与延迟口径需重新设计，不静默把文本转语音后当文本同条件排名。
D 人工执行导入：可作为替代，但当前尚无完整导入功能，需另行实现来源、转写复核和证据绑定。

本方案的开发主线是A或B；C、D不视作默认已授权实现范围。

## 4. 最小协议验证：先一条、再多轮

### 4.1 顺序与退出条件

1. 固定测试身份及目标角色，记录官方接入资料版本。
2. 获取官方要求的连接信息/完成激活，不执行固件升级。
3. 握手成功后发送一条无敏感信息的问题，收集完整回答与完成证据。
4. 两轮对话验证上下文；新建第二会话检查残留，不能只靠断开WS就宣称清除记忆。
5. 模拟超时/断连，保留部分结果、错误类别和资源释放证据。
6. 以有限次数调查定位差异，未确认入口则回到调查，不无限试错和盲重发。

门槛：问题实际进入指定角色，取得完整可解释结果，而不只是HTTP200或WS连接成功。

### 4.2 现有协议不可直接照搬的点

| 当前代码 | 小智接入需确认 |
|---|---|
| WS查询参数authorization/device-id/client-id | 是否实际要求请求头、协议版本或其他授权字段 |
| hello中device信息、token、features.mcp | version/transport/audio参数及字段要求 |
| listen/manual/detect/text | 是否支持任意完整文本，而非仅唤醒检测 |
| hello首个接收包必须是hello且有session_id | 官方是否有前置事件、会话标识及消息附带要求 |
| LLM/TTS文字片段拼接 | 是否同源重复、是否有message/segment ID与最终回答事件 |
| tts stop加静默作为收尾 | 官方停止语义及慢速回复能否完整收集 |
| 每轮通告工具清单并占位响应 | 首期文本是否应关闭MCP；未经授权不注入自家工具 |
| 所有设备按MAC互斥 | 官方账号/设备/角色绑定对应的实际资源键 |

差异仅进入对应适配器，不修改自家原协议去迁就竞品。公共代码的bug修复需独立说明并回归。

## 5. 目标架构与渐进改造

```text
现有Streamlit：玩具管理 / 测试集 / 评测执行 / 结果
                         ↓
             单对象入口 / 新增对比任务服务
                         ↓
               固定公共测试与规则快照
                         ↓
          自家子任务                   小智子任务
             ↓                            ↓
   LegacyToyAdapter              XiaozhiOfficialAdapter
   原有设备采集链路               经验证的官方入口
             └──────── 统一采集结果 ────────┘
                         ↓
              既有裁判与规则评分服务
                         ↓
       独立报告 + 对齐/覆盖率/同题对比报告
```

### 5.1 自家适配器采取外包裹式迁移

先包装现有采集流程，不移动或重写所有采集器。抽出“采集结果返回”边界，旧run_framework仍负责兼容的采集→评分→报告；新比较服务可复用采集结果而不重复评分。不能先跑原完整链路再在父任务重打一次分。

首期统一契约按会话组采集，保护当前类型会话语义；协议验证器内部仍可以逐条send。这样避免一次性把所有testers重构为逐轮通用框架。

### 5.2 受控适配器契约（拟议）

- validate_config：本地校验，不联网。
- check_connection：用户明确触发的连接验证，不自动跑公共集。
- capabilities：返回声明状态、验证证据和日期。
- collect_session：接收已固定的会话组，顺序执行所有轮次，返回逐条结果。
- close/cancel：明确本地资源关闭和是否支持远端取消。

内部实现可细分create_session/send_message/close_session，但不要求第一阶段重写全部自家采集器。受控注册表只接受已安装的适配器ID，不配置任意Python模块或可执行脚本。

### 5.3 小智适配器

根据A/B路线选择具体实现，只有一个实际确认的路线进入首期。配置缺失即报错，不自动换成社区后端、模型API或另一个官方角色。

没有完整结束证据时保留partial_answer，标记incomplete/timeout，不将其作为正常完整回答评分。工具证据不可见记unobservable，不填空列表来声称没有调用。用量未知为null，不填0；不采集或展示内部推理链。

## 6. 配置管理：保持简洁，增加必要的高级入口

保留自家“名称+Token”接入体验。新增按钮可先选择“自家玩具/外部Agent”，默认自家；外部表单仅展示所选适配器所需字段。

建议继续扩展已有toy档案，由旧id兼容映射agent_id，暂不迁移目录；缺省adapter=legacy_toy。新增字段拟议如下，并非当前已实现：

- adapter、adapter_revision、provider、service_origin。
- target_role_label、binding_description、config_revision。
- input_mode及已验证状态。
- 适配器受控连接参数与凭据引用；UI密码输入后仍保存加密引用。
- resource_key、timeout、max_concurrency、min_request_interval、max_cases、max_requests。
- capabilities及evidence_ref/verified_at。

现有环境模型仅允许固定设备字段，不能直接把外部参数塞进环境字典绕过校验；应按适配器独立定义配置Schema。官方可能需要激活身份/运行Token多种凭据，分开管理生命周期，不复用自家公司Token。

Windows DPAPI绑定当前用户/机器使用条件，不能把密文直接复制到Linux Runner并认为可解密。部署变更需环境变量或重新配置，不导出明文。

## 7. 公共测试集与公平条件

### 7.1 首批集

建议从小批量开始，例如约10条，数量只是准备建议。先基础问答、安全、情感；短期上下文需完成会话验证后纳入。

首期排除：设备电量/音量/关机等工具规则、产品专有知识、长期记忆共同排名、不同资料下的知识库对比。天气等实时问题即使模型可评分，也需要可核对的时间地点与事实证据；首批建议少用，避免把表达质量当事实正确性。

已有98条不全部套用、不覆盖：另建公共验证集。自定义类型可复用，但映射到设备MCP/未验证能力时明确排除。

### 7.2 同一快照、稳定对齐

当前数据集快照会被每个worker分别制作；对比任务必须改为父任务先制作一次只读公共快照，所有子任务使用同一份不可变版本/副本及相同hash。否则两次执行间修改用例会失去公平性。

父任务为当次每条用例分配comparison_case_key，并保存dataset_id、工作表、原行、原编号、输入和预期hash。不能只按显示编号对齐，不同集可能同编号；不能按回答顺序猜测对齐。跨版本永久稳定ID后续补齐，本期使用“父快照版本+来源映射+当次UUID”足够保证同次比较。

### 7.3 会话策略

双方必须使用同一会话计划。首期可沿用“测试集+类别”作为冻结分组，记录普通问答也可能共享历史的限制；需要严格独立问答时另建明确单例会话计划，不能只重置一方。

记忆类的前置轮次不可丢失；组内永远顺序执行。不同对象、不同测试集不共享会话对象。官方无法验证隔离时，不能进入严格上下文对比，只作带限制的产品体验测试。

### 7.4 阈值与裁判公平

既有单条阈值包含toy_id，直接分别加载可能让两方标准不同。父任务应生成一份公共比较规则快照：公共分类/单条阈值按comparison_case_key统一投影，排除玩具专属覆盖，或要求显式审核成统一覆盖。自定义类别的rubric、基础方式和阈值也一并冻结。

所有对象使用同一选中裁判、模型ID、兼容参数、阈值及分数校验。首期保持等权平均、任一选中裁判失败则评分失败。不加权、不新增“赢家裁判”改变规则。

裁判输入不注入厂商标签；用户问题本身含身份内容时不擅自改写原回答。保留原回答证据和实际判分输入，以便审计。

## 8. 总任务、子任务与状态持久化

### 8.1 首期串行而非并行

先执行两个独立子进程，父任务逐个调度；一个失败后继续下一个。多选不等于并行。待额度和资源锁验证后再加入受控并发。

保留单玩具入口。新增comparison服务和独立父任务，不把现有JobManager的device_mac字典硬改成同时承担父任务、调度与状态数据库。

### 8.2 建议存储

```text
reports/comparisons/<comparison_id>/
  task.json                 父任务状态和非敏感快照引用
  manifest.json             对象、公共集、会话计划、裁判与规则版本
  inputs/                   冻结公共集与来源映射
  children/<child_id>/       独立状态、脱敏日志、结果与原格式报告
  comparison.json
  comparison.xlsx
  comparison.md
```

所有状态原子写入；父目录不存真实Key。路径限制在报告根目录，证据限制数量/大小；日志脱敏包括OTA返回的新Token。

### 8.3 状态契约

执行状态：queued/running/completed/failed/timeout/cancelled/incomplete/uncertain。
评分结论：passed/failed/judge_error/not_applicable/insufficient_evidence/not_evaluated。

两者分开。单条judge_error不自动等于子任务执行失败；已完成质量不通过也不等于执行异常。新比较状态先由比较读取层处理，旧四状态报告读取仍保留。不可为新状态把旧标签全量改写。

父任务保留partial_completed及各子状态。UI刷新读文件，不靠SessionState保存任务事实。服务进程重启后通过心跳/进程状态识别失联；不假装恢复原Popen句柄，也不自动重发状态不明的请求。

### 8.4 超时、取消、重跑

分别定义连接、首个有效事件、单轮总时长、会话、子任务及总任务上限；具体数值由接入测试和额度确认，不把现有45秒直接当官方规范。

取消先停止提交新轮次，再关闭本地会话，支持官方远端取消才发送取消；否则标注仅本地停止/远端状态未知。重跑建立新ID，关联原任务；不得覆盖原报告。只有明确安全的连接/查询可有限重试，已提交问题超时不盲目重复提交。

资源锁按实际账号/设备/绑定资源定义：旧自家设备MAC继续锁定；同一物理设备/账号的不同档案不得绕过互斥。

## 9. 统一结果和报告

每条结果至少含：schema_version、comparison_id、child_id、agent_id、config_revision、comparison_case_key、来源映射、category/base_handler、session_group/turn、execution_status、answer/partial_answer、completion_evidence、duration、usage、tool_observability、error_type、evidence_ref、judge_result。

保留原报告核心字段，通过桥接映射为既有judge可消费的数据，不为接入额外造一套评分公式。

### 9.1 统计口径

设N为本次选择的公共用例数；对每个对象分别统计：

- A：适用数；C：完整执行数；J：成功获得有效语言评分数。
- P：业务通过数；F：有有效判定的业务失败数。
- 适用覆盖率=A/N，执行覆盖率=C/A，评分覆盖率=J/A；分母0显示不可计算。
- 单体业务通过率=P/(P+F)，保持排除评分错误与未评估的既有原则，同时显示排除数量。
- 平均语言分仅有效语言得分；MCP规则分不混入。
- 对齐比较集K：双方共同适用、完整执行且成功评分的同一用例交集，明确显示K/N及被排除原因。

单体全量分母与K上的成对结果分开展示，不能拿不同分母的通过率直接排名，也不能隐去覆盖率。K只是本次可比证据，不代表未完成部分表现良好；样本不足时不宣称总体领先。

同题页展示输入、统一预期、双方实际回答、分数、理由、执行状态和耗时。耗时定义为发送文本到完整回答，不命名为语音首包延迟；不同采集收尾等待差异要记录。费用未知不估算、用量未知为null。

### 9.2 防止旧结果混算

对比报告只引用父任务的显式子结果映射，不扫描最近两份报告凑对。历史独立报告没有相同公共/规则/会话快照时，只能人工查看，不能补造可比性。

新compare schema使用独立版本；旧schema_version=2及无版本报告继续原读取。当前动态裁判Excel列继续复用，对比Excel另外提供任务摘要、覆盖率、分类和同题结果，不改写源用例。

## 12. 分阶段任务与验收门槛

### P0：调查、范围与基线

- 负责人完成账号/角色/绑定/授权/文本入口/额度调查。
- 留存当前自家小范围真实报告及脱敏配置hash。
- 准备审核过的公共验证集、统一规则与会话计划。
- 确定A/B路线；不能确定则只继续通用模拟开发。

交付：调查表、权限/预算边界、基线、公共集草案。门槛：有允许使用且可执行的入口。

### P1：最小协议验证

- 单轮完整回答、两轮上下文、独立会话、断连和超时。
- 取得脱敏报文、结束条件和目标角色证据。
- 不跑全量、不启用定时。

交付：协议差异表、验证脚本/记录、能力状态。门槛：实际进入目标Agent，不只是连接成功。

### P2：单对象适配与兼容

- 定义会话组采集契约、legacy包装、小智具体实现。
- 外部高级配置与安全凭据、结果桥接、独立报告。
- 原设备、单CLI、工具规则、动态裁判、自定义类型、旧报告回归。

门槛：公共集分别对两对象执行评分；自家行为无意外变化。

### P3：父子任务与对比闭环

- 父任务一次冻结公共集、规则、会话计划及裁判。
- 首期串行独立子进程，失败隔离、状态和日志持久化。
- 对齐键、统一阈值、覆盖率、K集及三种对比附件。
- 页面对象多选、兼容矩阵、规模确认和同题查看。

门槛：任一对象失败另一个仍出报告；刷新恢复状态；无不同版本数据混合比较。

### P4：真实小批量验收

- 按授权身份、次数、频率执行真实公共验证集。
- 核对每条回答、结束证据、评分、来源和附件。
- 故障场景优先本地模拟，不故意影响官方服务。
- 形成可复现结论与能力限制，业务负责人验收。

门槛：完整可追溯、分母一致、覆盖率可解释，不把本地mock当官方成功。

### P5：可选自动化与扩展

验收且取得额度授权后再接每日/事件比较任务；之后按真实需求加受控并发、其他厂商或语音/人工导入。Work路线继续单独待办。

## 13. 测试矩阵

| 测试层 | 最低覆盖 |
|---|---|
| 纯单元 | 配置与注册白名单、凭据引用、不支持能力、对齐键、统一阈值、覆盖率分母、无效评分、旧schema |
| 脱敏报文回放 | 正常握手、前置事件、重复文字、乱序片段、stop前后慢事件、工具不可见、结束缺失 |
| 本机模拟服务 | OTA/WS/API实际库交互、鉴权序列化、超时、断流、资源释放；不外网 |
| 父子进程 | 某子失败继续、共用快照、同设备互斥、取消范围、强退、重启失联状态、重跑新ID |
| UI | 保存不联网，多选实际传参，能力冲突提示，任务刷新，正确报告/附件，旧菜单不报错 |
| 安全 | stdout/stderr/异常/原始事件/URL全链脱敏，无明文配置与命令行Key，报告路径/大小限制 |
| 获授权真实 | 单轮、多轮、隔离、完整回答、角色绑定、真实评分与两份独立/一份比较报告 |

本地全套通过只说明代码/模拟验证成功，官方线上单独列状态。费用、延迟、长期记忆清理未验证就明确未验证。

## 14. 风险与处理

- 官方协议公开≠自动化许可：先确认，不抓取私有接口。
- 文本不可用：不硬套detect，改走另行批准的语音或人工方案。
- 自家与小智工具不同：公共集排除，不人为判对方工具失败。
- 父任务阈值按toy_id不同：统一公共规则投影，拒绝不一致快照。
- 注册配置运行中变化：父任务固定不可变内容，不在每子任务重新读最新文件。
- 流中断只有部分回答：执行未完成，不生成正常质量得分。
- 提交超时：保留uncertain，禁止无条件自动重发。
- 一个对象高分低覆盖：同时展示K/N、执行覆盖率和排除项，不直接宣布领先。
- 模型/服务版本未知：记录官方未披露及测试时间，不能推断。
- Windows密文跨机器：重新配置或采用部署侧环境引用，不复制密文假设可用。
- 现有菜单热更新缓存旧模块：涉及模块新增后先确认无任务再重启原服务，在原URL验证；不能仅以健康HTTP200证明所有菜单可用。

## 15. 开工前需你提供/确认

1. 小智官方账号与专用设备是否已有，具体测试哪个角色和绑定关系。
2. 官方确认可用的接入路线及资料：A文本API还是B授权客户端；无需把密钥发聊天。
3. 文本直入是否实测成功；若未实测，授权P1的调用范围和次数。
4. 两边是否按共同能力比较，而非完整产品默认体验；推荐前者。
5. 首批公共集、双方人设差异及评分标准由谁审核。
6. 最大用例数/重复次数/请求频率/并发/费用额度/测试窗口/数据外发范围。
7. 新外部配置采用独立高级入口，保留自家两字段简单体验；首期JSON目录存储和串行执行是否按此批准。

不需要一次补齐所有长期信息。先确认1–3及最小预算即可推进协议验证；P2/P3可用模拟服务独立实施，但真实接入结果必须在授权条件下验证。

## 16. 总结

推荐路径：接入调查与授权 → 一条真实问题闭环 → 多轮/隔离确认 → 薄适配器接入现有评分 → 父任务同快照双对象评测 → 覆盖率与同题对比 → 小批量真实验收。

本期不需要重建平台；最大的新增不是工具管理或裁判配置，而是“官方协议适配、一次冻结的多对象任务、严格结果对齐和比较口径”。这些完成后才具备可信的小智官方竞品评测能力。
